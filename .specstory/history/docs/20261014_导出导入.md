# 导出 / 导入设计与使用

> 作者：ygw

## 入口

「设置 → 数据」：导出备份、导入备份、清除本地数据；Cursor 明细页与 DeepSeek 账单页右上角有「导出 CSV」（导出的是当前筛选后的数据）。

## 备份文件（JSON）

```json
{
  "format": "ai-usage-backup",
  "schemaVersion": 1,
  "exportedAt": "2026-10-14T10:00:00Z",
  "appVersion": "1.0.0",
  "settings": {},
  "cursorEvents": [],
  "deepseekDaily": [],
  "snapshots": [],
  "kv": {},
  "credentials": {}
}
```

- `credentials` 只在导出时勾选「同时导出登录凭据」才会出现（明文，界面有风险提示）；默认不含。
- 写文件用「临时文件 + 改名」原子写入，权限 0600，写到一半断电不会留下半个文件。

## 导入流程

1. 选择文件 → 解析并校验 → 显示预览（条数、时间范围、导出时间、是否含凭据、将忽略的无效记录数）。**此时不改动任何数据。**
2. 选择方式：
   - **合并（默认）**：按去重键合并，本机独有的数据保留；重复导入同一个文件不会产生重复；「最近状态」只在备份更新时才覆盖。
   - **覆盖**：先清空本机数据再以备份为准；需要二次确认；覆盖前自动在 `备份目录/backups/` 留一份安全备份（保留最近 5 份）。
3. 可选项：同时采用备份里的设置（默认保留本机设置）；同时恢复凭据（默认不恢复，且仅当文件含凭据时才出现）。
4. 整个写库在一个事务里，任何一步失败整体回滚，本机数据保持不变。

## 容错

| 情况 | 行为 |
| --- | --- |
| 空文件 / 非 JSON / 数组 / 别的应用的 JSON / 截断文件 | 拒绝，给出明确中文原因 |
| 备份里没有任何有效数据 | 拒绝（避免「覆盖」把本机清空却什么都没导入） |
| `schemaVersion` 比当前新 | 拒绝并提示升级应用 |
| 旧版文件（没有 format / schemaVersion） | 自动迁移（补默认值、补去重键、规范化设置），预览里标注「旧版备份」 |
| 个别记录无效（时间为零、数值为 NaN/负数、日期格式错等） | 剔除并计数，其余照常导入 |
| 超过 256 MB | 拒绝 |
| 取消文件对话框 | 静默，不改动任何东西 |

## 清除本地数据

需要二次确认；清除前同样自动备份；钥匙串里的凭据不会被删除；可用自动备份文件再导入恢复。
